# How Geo Explorer works

This is a tour of how the game is put together, written for someone comfortable with Python or R
but new to web apps. There are two halves:

1. **A data pipeline in Python** (`scripts/`) that turns open datasets into compact JSON files.
2. **A single web page** (`src/template.html` → `index.html`) that holds all the game logic in plain
   JavaScript, with no frameworks and no server. All the data is baked into the page.

```
open datasets ──► scripts/build_*.py ──► data/*.json ──┐
                                                        ├──► scripts/build_page.py ──► index.html
                         src/template.html ─────────────┘
```

## Repository map

| Path | What it is |
| --- | --- |
| `index.html` | The finished game (about 2 MB). This is what GitHub Pages serves. Don't edit it by hand: it is regenerated. |
| `src/template.html` | The game's real source: styles (CSS), screens and logic (JavaScript). Has placeholders like `__DATA__` where the data goes. |
| `data/countries.txt`, `territories.txt` | One line per place: `CODE|Name|Capital|Region|tier`. Tier 1 = very well known, 5 = obscure. Hand-written. |
| `data/italian.txt` | Italian names and capitals, `CODE|Nome|Capitale`. Hand-written. |
| `data/extra_cities.txt` | Famous non-capital cities for the Cities game, `CODE|Name|tier`. |
| `data/*.json` | Generated by the scripts. Committed, so you can rebuild the page without downloading anything. |
| `scripts/` | The Python build steps (below). |
| `vendor/` | Downloaded source datasets. Not committed (`fetch_sources.sh` recreates it). |

## Part 1: the data pipeline

### Flags (`build_flags.py` → `flags.json`)

- Reads each country's SVG file from **flag-icons**, strips comments and anything script-like, and
  squashes whitespace. The SVG text goes straight into the JSON. In the browser, each one is turned
  into an image with `URL.createObjectURL(new Blob([svg]))`.
- **Look-alike flags** (used as tricky wrong answers): every flag is drawn at 32×24 pixels in a
  headless browser (Playwright). Two flags are compared on:
  - a colour histogram (64 colour bins), and
  - the average pixel difference, also against the left-right mirror image, so flags that are
    the same design flipped still count as alike.

  The 14 closest are stored in `sim`.

### Country outlines (`build_shapes.py` → `shapes.json`)

- Source: per-country GeoJSON from **mledoze/countries**.
- Each country is projected with a **Lambert azimuthal equal-area** projection centred on itself,
  so shapes aren't stretched the way they are on a world map.
- Small far-away islands are dropped (e.g. the Galápagos for Ecuador, Svalbard for Norway). The US
  is mainland only. Morocco is clipped at 27°40'N so disputed Western Sahara isn't drawn as part
  of it.
- Lines are simplified with the **Douglas–Peucker** algorithm (`geo_utils.simplify`), fitted into a
  100×100 box and written as an SVG path string.
- Similar outlines: each outline is rasterised to 32×32 and compared by overlap (intersection over
  union), with a small bonus for the same region.

### World map (`build_world.py` → `world.json`)

- The same outlines in plain longitude/latitude, simplified more heavily, for the globe and the
  city maps.
- To keep it small (about 60 KB), coordinates are stored as integers in tenths of a degree, and
  each point is stored as the difference from the previous one (delta encoding). The page decodes
  them on load.

### Cities (`build_cities.py` → `cities.json`)

- Capitals come from `flags.json`; famous extra cities from `extra_cities.txt`.
- Their coordinates and Italian names are looked up in **Natural Earth populated places**, by
  matching names (accents and punctuation ignored) within the right country.
- A dozen places Natural Earth doesn't list are filled in by hand in `MANUAL`.

## Part 2: the web page

### How a page like this works

`index.html` contains three kinds of thing:

- **CSS** in `<style>`: all the visual design.
- **Data** in `<script type="application/json">` blocks: the browser ignores these until the code
  reads them.
- **JavaScript** in one `<script>`: the whole game.

There is one empty `<div id="app">`. Every screen is drawn by a function that builds an HTML
string and puts it in there (`app.innerHTML = ...`), then attaches click handlers ("wiring") to
the buttons it just created. Nothing is hidden or shown: the screen is simply redrawn.

That gives one function per screen:

| Function | Screen |
| --- | --- |
| `renderHome()` | Home: today's tour, globe, flag of the day, game cards |
| `renderSetup()` | A game's setup: how to play, Start, Options |
| `renderQuestion()` + `answer()` | A question, and what happens when you answer |
| `renderSummary()` | End of a level |
| `renderAllDone()` | End of an "every one" run |
| `renderTourDone()` | End of today's tour |
| `renderStamps()` | The passport |

### State

Everything about "where you are" lives in one object, `state`:

- `topic`: `flags` / `capitals` / `shapes` / `cities`
- `game`: `levels`, `all` or `tour`
- `region`, `level`, `qIndex` (question number), `results`
- `current`: the current question, as `{ answer, options }`
- `view`: which screen is showing, so switching language can redraw the same screen

The tour mixes topics. Rather than overwrite your saved choices, it sets a temporary override
`ov`, and the helpers `TP()`, `MD()` and `RG()` return the topic, mode and region in effect for the
current question.

### Making a question

- Every place has a tier (1–5). A region's places are sorted by tier and split into five bands.
  Level *n* mostly asks from band *n* (70% of the time), sometimes from the easier ones.
- Six options are built by `buildOptions()`:
  - the right answer;
  - a number of "tricky" ones, which grows with the level (`TRICKY = [0, 0, 1, 2, 4, 5]`): look-alike
    flags, similar outlines, or capitals from the same part of the world;
  - the rest filled from places of similar fame.
- **"Every one" mode** keeps a queue: correct answers leave it, wrong ones go to the back. The
  queue is saved after every answer, so you can stop and resume.
- **Today's tour** and the **flag of the day** use a small seeded random-number generator
  (`seeded()`, a "mulberry32"), with the date as the seed. Everyone gets the same picks on the
  same day, without needing a server.

### Answering and scoring

- There is no timer on screen. The time from showing a question to answering is still measured
  (`performance.now()`), and used only for the "Quick!" badge, the averages on the results
  screens, and personal bests.
- A right answer moves on by itself after 0.65 s (1.3 s for cities, so you can see the map). A
  wrong one waits and reveals the names of all the options.
- **Cities:**
  - The map uses a **Mercator** projection (`mercY`), and your click is converted back into
    longitude/latitude.
  - The distance to the real city is the great-circle distance (the **haversine** formula, in
    `kmBetween`).
  - It counts as right within a distance that depends on the region: 150 km in Europe, up to
    350 km in Asia.

### What's saved

The game uses the browser's `localStorage`: small key–value storage that belongs to one browser
on one device. Keys start with `geo-`:

| Key | What it stores |
| --- | --- |
| `geo-flags-learned` (and `capitals` / `shapes` / `cities`) | Everything you've ever got right. Drives progress bars, stamps and the green globe. |
| `geo-all-…` | An unfinished "every one" run. |
| `geo-best-…` | Personal bests per level. |
| `geo-tour-YYYY-MM-DD` | Today's tour result. |
| `geo-settings-v2`, `geo-holder` | Your settings, and the name in your passport. |

Nothing is sent anywhere. Clearing the browser's site data resets everything.

### Stamps and "what next"

- A region's stamp is earned when every place in that region is in the "learned" set for that
  game (`stampProgress`).
- `suggestNext()` picks the button shown after you finish something. It prefers a region you've
  started but not finished in the game you were playing, then any unfinished region, then the
  next game.

### Languages

All wording lives in one table, `T`, with an `en` and an `it` section. `L()` returns the current
one. Country names come from the data (`n` / `ni`, capitals `cap` / `capi`). Adding a language
means adding a third section to `T`, plus a column of names in the data.

### Themes

Colours are CSS variables (`--bg`, `--ink`, `--sun`…). The "Playful" theme just redefines them
under `body[data-look="playful"]`, and adds a few touches like the clouds, bouncy cards and
confetti.

### The globe

- Drawn on a `<canvas>` with an **orthographic** projection: the globe as seen from space
  (`drawGlobe`).
- Points on the far side are pushed to the edge of the circle, which is a cheap way to keep shapes
  that cross the horizon looking right.
- It redraws about 60 times a second with `requestAnimationFrame`. Dragging changes the centre
  longitude and latitude. Revealing the flag of the day sets a target the globe glides towards.

## Common changes

- **Fix or translate a name:** edit `data/countries.txt` or `data/italian.txt`, then run
  `build_flags.py` and `build_page.py`. If it's a capital, also run `build_cities.py`.
- **Make something easier or harder:** change its tier in `data/countries.txt` (or
  `extra_cities.txt`).
- **Add a city:** add a line to `data/extra_cities.txt`, then run `build_cities.py` and
  `build_page.py`.
- **Change wording, colours or layout:** edit `src/template.html` (wording is in the `T` table near
  the top of the script), then run `build_page.py`.
- **Try a change quickly:** after `build_page.py`, open `index.html` in your browser and refresh.

## Known limitations

- Progress lives in one browser. Playing on a phone and a laptop gives two separate passports.
- Map borders are simplified, and some tiny islands aren't drawn (Port Vila sits on one).
- Kosovo has no outline in the source data, so it isn't in the Shapes game.
